# 용량 제한 규칙 적용 — 2026-11-06

> 아래 용량 초과·차단 상태는 규칙을 처음 적용한 시점의 기록이다. 이후 [과거 증거 정리](evidence-archive-2026-11-06.md)로 활성 증거를 약 27.8GiB로 줄였으며, 용량 검사와 대표 QA 목록 조회가 통과했다.

기존 정리 원칙을 `storage-policy.json`, `scripts/storage.mjs`, npm 명령과 브라우저 QA 진입점에 연결했다. 도메인·화면·데이터 계약은 변경하지 않았다.

## 적용 기준

- 새 관리 실행 1GiB, `.artifacts/` 전체 5GiB, 실제 여유 공간 최소 10GiB.
- 성공한 일회성 테스트 결과는 최소 7일 및 같은 명령의 최신 성공 3회를 보존한다. 둘 다 벗어난 실행만 `storage:clean -- --apply`의 삭제 대상이다.
- 실패·미완료·수동 실행·살아 있는 소유 PID·불명확한 마커·심볼릭 링크·`.keep`는 자동 삭제하지 않는다.
- 과거 `.omo/evidence/` 30GiB 초과 시 `npm run test:e2e`와 `tools/qa/run.mjs`에서 새 브라우저 실행을 시작하지 않는다.
- 관리 wrapper는 실행 전·중·자손 종료 후 용량을 확인한다. 예산 초과로 중단한 실행을 성공으로 기록하지 않는다. 소유 프로세스 종료를 확인한 뒤 임시 runtime을 정리한다.

## 실제 검증과 적용 결과

| 확인 | 결과 |
| --- | --- |
| 격리된 정리 도구 테스트 | 15/15 통과. 삭제 허용·보존, 외부 경로 거부, 예산 초과, 자식 exit code, 신호 전달, 종료 중 마지막 쓰기 포함. |
| 실제 `npm test -- src/operations/scene/assets/loader.test.ts` | 27/27 통과. 증거 24개가 새 관리 폴더에 생성되고 runtime은 제거됨. |
| `storage:report`, 일반 `storage:check` | 성공. 일반 단위 테스트는 과거 증거 크기 때문에 차단되지 않음. |
| `storage:clean` 및 `storage:clean -- --apply` | 실제 실행. 최근 성공 실행은 최신 3회 보존 규칙에 따라 유지됨. 이번 적용에서 삭제 대상 0건. |
| 직접 browser QA 진입점 | 30GiB 초과로 nonzero 종료, 지정한 새 evidence 폴더가 생성되지 않음. |
| `npm run test:e2e -- --list` | pretest 검사에서 nonzero 종료. Playwright 시작 전 차단됨. |
| 필수 과거 입력 18개 | 기존 보존 목록의 SHA-256과 모두 일치. |

적용 시 과거 증거의 논리 크기는 126,762,656,825바이트(약 118.1GiB)였다. 따라서 현재 새 브라우저 QA는 의도적으로 차단된다. 새 관리 영역은 로더 검증 후 약 2MB이며, 오래된 증거를 임의 삭제하거나 한도를 올려 검사만 통과시키지 않았다. 과거 증거의 중복 블록·APFS clone 때문에 이 논리 크기를 실제 디스크 점유량으로 해석하지 않는다.

독립 검토에서 자손의 종료 핸들러가 마지막으로 쓴 파일을 놓치는 경우를 발견했다. 수정 전 실패를 재현하고, 소유 그룹의 종료 후 최종 검사와 회귀 테스트를 추가했다. 구현은 명시적으로 배정된 Sol High, 통합 검토는 Astra High에서 수행했다. 이전 전체 프런트엔드 테스트 실패의 수정이나 전체 제품 검증은 이번 범위에 포함하지 않는다.

## 운영상 한계

250ms 주기 검사이므로 검사 사이의 큰 쓰기가 상한을 일시적으로 넘을 수 있다. OS 수준의 파일시스템 quota는 아니며, 관리 경로 밖에 직접 생성하는 모든 파일을 막지는 않는다. 브라우저 QA에는 시작 전 검사만 적용했으며 실행 중 감시까지 전환한 것은 아니다. 기존 서비스·DB·원본 자산·유일한 과거 증거는 보존했다.

사용 명령과 아카이브 절차는 [저장소 정리 원칙](../REPOSITORY_HYGIENE.md)에 있다. 원시 로그·리뷰·삭제 dry-run 결과는 로컬 `.cleanup/storage-policy-v2/`에 보관한다.
