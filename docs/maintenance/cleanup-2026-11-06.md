# 2026-11-06 저장소·디스크 정리 기록

첫 Git 커밋을 준비하며 현재 개발 스냅샷을 보존했다. 기존 커밋과 원격 branch는 없었고, `origin`은 `https://github.com/Kalamari0227/steelflow_erp.git`이었다. 기능 완료·전체 통합 수락을 의미하지 않는다.

## 변경과 보존

- `.gitignore`: 로컬 실행 이력, 검색 인덱스, 브라우저 산출물, DB, 비밀 설정, 대형 QA 녹화를 제외했다.
- `.gitattributes`: 109,638,809바이트의 `shared/fixtures/finishing-continuity-cases.json`만 Git LFS로 보관한다. JSON 바이트는 변경하지 않았다. 다른 개발 환경도 Git LFS가 필요하다.
- `.omo`의 직접 참조 입력 18개, 약 14.4MiB는 [해시 목록](retained-test-inputs.json)과 함께 Git 예외로 보존한다. 합성 마이그레이션 DB도 포함하며 실제 실행 DB와 구분한다.
- 오래된 쓰기 가능한 증거의 동일 바이트 사본 9,321개, 논리 크기 약 38.44GiB를 APFS copy-on-write clone으로 교체했다. 각 교체 전 SHA-256과 파일 변경 여부, 복제 결과를 확인했다. 경로·내용·권한·수정 시각은 유지했고 읽기 전용 디렉터리는 제외했다. 하드링크는 만들지 않았다.
- 루트의 HTTP 결과, `mutants/`, `--root` 오배치 파일을 `.omo/evidence/recovered-root-20261106/`에 보존했다. 과거 브라우저 보고서 중 원본과 SHA-256이 같은 45개 파일(286,113,897바이트)만 삭제하고, 일치 사본을 찾지 못한 파일은 같은 복구 폴더로 옮겼다.
- 사용하지 않는 CodeGraph DB·pytest/ruff 캐시와 이번 검증용 임시 빌드를 정리했다. 기존 `dist`, 설치 의존성, 원본 자산, 실행 DB, 4180/8180 서버는 유지했다.
- `.git` 임시 파일 중 사용 종료와 10분 경과를 확인한 2개(약 1.12GiB)를 삭제했다. 사용 중인 나머지 pack과 최근 미참조 객체는 보존했다. `prune --expire=now` 또는 이력 재작성은 하지 않았다.

실제 파일시스템 여유 공간 변화는 [측정 JSON](cleanup-2026-11-06.json)에 있다. APFS 공유 블록 때문에 `du`의 논리 합계와 실제 확보 공간은 다르며, 동일 볼륨의 다른 작업도 `df` 차이에 영향을 줄 수 있다. 개별 교체·삭제·이동 영수증과 원시 실행 로그는 로컬 `.cleanup/` 및 복구 폴더에 남겼다. 제외된 과거 영상·trace는 원격 저장소에 백업되지 않는다.

## 남은 기존 문제와 다음 단계

1. `src/operations/scene/visualTokens.test.ts`: 9개 실패. 현재 시각 검토 목록에서 `coverage: missing, duplicate or unreviewed_variant row`가 발생한다. 검토 목록과 실제 variant/placement 범위의 일치 여부를 먼저 확인해야 한다.
2. `src/operations/scene/motion/bathPath.test.ts`: 11개 실패. SharedArrayBuffer·분리된 ArrayBuffer 입력에서 기대한 `binding` 오류 대신 원시 TypeError가 나온다. `bathPath.ts` 및 Python 대응 경계의 오류 계약을 Astra High로 정리한 뒤 Sol High에서 필요한 구현과 회귀 테스트를 진행한다.
3. 과거 finishing/transport 브라우저 runner에는 로컬 `.omo` 경로 및 실행 기한에 의존하는 항목이 남아 있다. 첫 clone만으로 모든 역사적 QA를 재현할 수 있다고 주장하지 않는다. 현재 필수 단위 테스트 입력과 대용량 과거 증거를 구분해 후속 이관한다.
4. 모델 캐시에 Sol/Astra와 High/Ultra 선택지가 있음을 확인했으나 현재 실행 모델·추론 수준의 실측 증명은 제공되지 않는다. 이번 작업은 저장소/디스크 정리에 한정했고, 위 도메인·오류 계약 수정은 실행하지 않았다.
