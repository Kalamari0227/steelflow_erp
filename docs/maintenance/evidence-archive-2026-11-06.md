각 압축본의 모든 파일을 실제 임시 파일로 복원하여 원본 SHA-256과 대조했다. 압축본 전체와 manifest 해시를 기록하고, 원래 파일의 변경 여부·해시를 다시 확인한 뒤 일치한 원본만 정리했다. 복원 파일은 확인 직후 정리해 임시 복원본이 누적되지 않게 했다. 아카이브별 크기·해시·파일 수는 [기계 판독 목록](evidence-archive-2026-11-06.json)에 있다.

현재 테스트·제작 도구가 참조하는 파일, finishing 준비 자료와 참조 원본, transport 작업 원본, 최신 재개 작업은 기존 위치에 남겼다. 최근 파일·심볼릭 링크·읽기 전용 디렉터리 내부는 정리 대상에서 제외했다. 실행 중인 서비스를 종료하거나 권한을 바꾸지 않았다. 과거 실패 증거도 압축 보관본에서 복원할 수 있다.

## 실행 확인

- 필수 과거 입력 18개의 SHA-256이 기존 보존 목록과 모두 일치한다.
- 코드·테스트의 직접 참조 경로 21개가 모두 존재한다.
- coverage/fleet release/traffic provenance 백엔드 회귀 검사: **165 passed**.
- `node scripts/storage.mjs check --include-legacy`: **exit 0**. 기존 30GiB 기준을 통과한다.
- 관리 wrapper를 통한 `npm run test:e2e -- tests/factory-assets.spec.ts --list`: **exit 0**, 테스트 4개 발견. 시작 전 용량 검사가 통과하여 Playwright까지 진입했다.
- 테스트 파일을 지정하지 않은 전체 `--list`는 finishing의 명시적 고정 후보 환경 변수가 없어 실패했다(`Explicit pinned finishing candidate required`). 해당 실패는 용량 차단이나 아카이브 누락 오류가 아니다. 그 실행 기록은 실패로 보존했다.

브라우저 테스트 본 실행·제품 전체 수락은 이번 정리 작업에 포함하지 않았다. 신규 QA는 요구되는 후보·fixture와 테스트 범위를 지정해 실행해야 한다. 과거 후보를 재현하려면 필요한 입력을 먼저 복원한다.

보관본은 같은 디스크의 로컬 파일이며 Git이나 별도 장치의 백업은 아니다. `.archives/`는 Git에서 제외했다. 복원 방법과 운영상 주의점은 [아카이브 복원 안내](../ARCHIVE_RECOVERY.md)에 있다. 로컬 실행·검증 로그는 `.cleanup/archive-2026-11-06/`에 남겼다.
