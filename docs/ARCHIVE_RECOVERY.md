# 과거 QA 증거 아카이브와 복원

2026-11-06부터 오래된 QA 작업 사본을 저장소 로컬 `.archives/evidence-2026-11-06/`에 압축 보관한다. 이 디렉터리는 Git에서 제외된다. 같은 디스크에 있는 압축 보관본이며, 별도 장치나 원격 백업을 뜻하지 않는다.

아카이브는 `작업묶음.tar.zst`, 같은 이름의 `.manifest.jsonl`, `.receipt.json`으로 구성한다. manifest에는 원래 저장소 상대 경로·크기·SHA-256·변경 확인 정보가 있고, receipt에는 압축 파일 해시와 복원 검증·정리 결과가 있다. 압축 파일과 manifest를 함께 보관한다.

## 이번 정리의 보존 기준

- 현재 코드·테스트가 직접 읽는 파일과 [필수 과거 입력](maintenance/retained-test-inputs.json)은 기존 경로에 둔다.
- finishing 준비 자료·참조 자산 원본, transport 작업 원본, 최신 재개 작업은 보존한다.
- 최근 수정된 파일, 심볼릭 링크, 읽기 전용 디렉터리 내부, 변경이 감지된 파일은 자동 이동·삭제하지 않는다.
- 과거 파일은 압축본에서 실제 임시 파일로 복원해 원본 SHA-256과 대조한 후에만 원래 위치에서 정리한다. 크기만 비교하거나 압축 성공 메시지만 보고 삭제하지 않는다.
- 압축 파일은 `.omo/evidence/`의 활성 자료 용량과 분리해 보관한다. 프로젝트 전체의 실제 점유량은 `du`와 디스크 여유를 함께 확인한다. 큰 아카이브를 추가할 때는 필요한 임시 공간도 계산한다.

## 복원 순서

1. 해당 receipt의 `status`와 압축 파일 SHA-256을 확인한다. `verified-before-removal`은 복원 검증까지 끝났으나 원본 정리가 완료되지 않았을 수 있다는 뜻이다.
2. 압축을 푼 크기만큼 여유 공간이 있는 별도의 빈 디렉터리를 준비한다. 실행 중인 프로젝트에 바로 덮어쓰지 않는다.
3. 아래 예시의 아카이브 파일명을 필요한 작업에 맞게 바꾸어 복원한다.

```sh
set -o pipefail
export STORAGE_RECOVERY_DIR="$(mktemp -d "${TMPDIR:-/tmp}/steelflow-restore.XXXXXX")"
zstd -dc .archives/evidence-2026-11-06/uf-20261030-resume06__task-21.tar.zst \
  | tar -xpf - -C "$STORAGE_RECOVERY_DIR"
```

4. manifest의 상대 경로에 대응하는 복원 파일을 SHA-256으로 대조한다. 파일 수·크기·해시가 모두 일치해야 한다. 원래 파일은 `$STORAGE_RECOVERY_DIR/.omo/evidence/...`에 복원된다.
5. 필요한 누락 입력만 원래 위치에 복사한다. 현재 파일을 덮어쓰지 않는다. 복원으로 `.omo/evidence/`가 30GiB를 넘으면 새 QA는 다시 차단되므로 필요한 입력 범위를 좁힌다.
6. 재현 확인 후 이번에 만든 임시 복원 폴더를 정리한다. 압축 보관본과 manifest는 유지한다.

앞으로 과거 기록을 추가로 아카이브할 때도 파일별 해시 목록 → 압축 → 실제 복원·대조 → 변경 여부 재확인 → 원본 정리 순서를 따른다. 유일한 실패 증거를 압축 보관본까지 삭제하는 작업은 이 절차에 포함하지 않는다.
