# 저장소와 디스크 정리 원칙

소스의 재현성과 검증 원본을 보존하면서, 임시 산출물이 Git과 디스크에 반복 축적되지 않게 관리한다. Git 제외는 파일 삭제나 백업을 뜻하지 않는다.

## 실행에 적용되는 용량 제한

`storage-policy.json`을 실행 기준으로 사용하고 `scripts/storage.mjs`가 검사한다. 단순히 Git에서 숨기는 것으로 정리를 대신하지 않는다.

| 항목 | 기본 한도·처리 |
| --- | --- |
| 새 관리 대상 실행 1회 | 1GiB. 실행 중 초과하면 도구가 시작한 프로세스를 종료하고 실패로 기록한다. |
| `.artifacts/` 관리 영역 전체 | 5GiB. 한도 도달 시 추가 실행을 거절한다. |
| 실제 디스크 여유 공간 | 최소 10GiB. 실행 전·중 검사한다. |
| 성공한 일회성 테스트 산출물 | 최소 7일 보관하며, 같은 명령의 최신 성공 3회는 추가 보호한다. 두 조건을 모두 벗어난 실행만 정리 가능하다. |
| 실패·중단·불명확한 실행 | 자동 삭제하지 않는다. 보존 또는 검증된 아카이브 후 수동 정리한다. |
| `.keep`가 있는 실행 | 보관 기간과 관계없이 자동 정리에서 제외한다. |
| 과거 `.omo/evidence/` | 논리 용량 30GiB를 넘으면 새 브라우저 QA를 시작하지 않는다. 오래된 증거의 자동 삭제 허가는 아니다. |

```sh
npm run storage:report             # 현재 사용량·보관 상태 확인
npm run storage:check              # 새 관리 대상 실행 가능 여부
npm run storage:clean              # 삭제 예정 목록만 확인
npm run storage:clean -- --apply   # 보관 조건을 만족한 성공 산출물만 정리
npm run test:storage               # 정리 도구의 안전성 테스트
```

일반 `npm test -- <테스트 선택 옵션>`은 이 도구를 통해 실행한다. 새 산출물은 `.artifacts/runs/<실행 ID>/evidence/`, 임시 파일은 같은 실행의 `runtime/`에 둔다. 자산 로더·Blender 파이프라인 출력과 임시/캐시 환경을 이 경로로 지정한다. 자기가 시작한 자식 프로세스가 종료된 뒤 runtime을 정리하고, 증거·종료 결과는 보관한다. 기존 `ASSET_*_EVIDENCE_ROOT`를 외부 경로로 지정하면 범위 밖 산출물을 감시한다고 오해하지 않도록 거절한다.

정리는 소유 마커가 유효하고 완료된 성공 실행에만 적용한다. 실행 중인 PID, 심볼릭 링크, 알 수 없는 마커, 실패 기록, `.keep`는 건드리지 않는다. 기존 `.omo`, 문서 증거, DB, 소스, 원본 자산, 설치 의존성, `.git`은 자동 삭제 범위가 아니다.

실행 중 검사는 250ms 간격의 파일 순회 방식이다. 검사 사이의 큰 쓰기로 한도를 잠시 넘을 수 있으므로 엄밀한 파일시스템 quota로 해석하지 않는다. 중단 후에도 자식 프로세스 그룹의 종료가 확인되지 않거나 runtime에 심볼릭 링크가 있으면 runtime을 보존하고 수동 확인이 필요한 실패로 기록한다.

`npm run test:e2e`와 `tools/qa/run.mjs`는 브라우저 실행 전에 과거 증거 한도도 검사한다. **2026-11-06 아카이브 정리 후 활성 증거는 약 27.8GiB이며, 용량 검사와 대표 QA 테스트 목록 조회가 통과했다.** [정리 결과](maintenance/evidence-archive-2026-11-06.md)에 보존·복원·검증 범위를 기록했다. 기존 브라우저 소유권·포트·연속 녹화 계약은 유지한다. 브라우저 QA는 아직 실행 중 용량 감시 대상으로 전환하지 않았으므로, 실행별 산출물 용량을 확인해야 한다. 직접 다른 명령으로 생성한 파일까지 OS 수준으로 제한하는 디스크 quota는 아니다.

과거 증거를 줄이려면 아래 아카이브 절차를 따른다. 한도를 임의로 늘리거나 검사를 우회해 반복 실행하지 않는다. 원래 경로가 필요한 필수 입력은 `maintenance/retained-test-inputs.json`과 코드 참조를 확인한 뒤 계속 보존한다.

과거 QA 압축 보관본은 Git 제외 경로 `.archives/`에 두며, [아카이브 복원 절차](ARCHIVE_RECOVERY.md)를 따른다. 실제 복원과 파일별 해시 대조를 마친 원본만 정리한다.

실제 적용·보존·차단 동작의 확인 결과는 [용량 규칙 적용 기록](maintenance/storage-policy-2026-11-06.md)에 남긴다.

## 보관 기준

| 구분 | 보관·정리 원칙 |
| --- | --- |
| `src/`, `backend/`, `tools/`, `scripts/`, 설정·잠금 파일 | Git에 보관한다. 실행 DB·캐시·가상환경은 제외한다. |
| `assets/source/`, `public/assets/`, `shared/`, `tests/fixtures/` | 원본 제작 자료와 실제 실행·테스트 입력이므로 보존한다. 크기만으로 삭제하지 않는다. |
| 대형 필수 파일 | `shared/fixtures/finishing-continuity-cases.json`은 정확한 바이트를 유지하는 Git LFS 파일이다. 복제 후 Git LFS를 설치하고 `git lfs pull`을 실행한다. |
| `docs/evidence/` | 문서·JSON·참고 이미지는 Git에 보관한다. 대용량 ZIP·영상은 로컬 원본으로 남기고 Git에서 제외한다. 새 clone에는 제외한 영상·trace가 없으며, 원본이 필요하면 별도 백업에서 가져온다. |
| `.omo/` | 실행 이력·실험·검증 작업 사본은 기본적으로 로컬에 보존한다. 현재 테스트/출처 검증이 직접 읽는 예외 파일만 Git에 포함한다. 정확한 목록과 SHA-256은 [필수 과거 입력 목록](maintenance/retained-test-inputs.json)에 있다. 이미 추적한 예외 파일은 일반 `git add`로 갱신할 수 있다. 새 예외는 의존성을 확인하고 목록을 갱신한 뒤 그 경로만 `git add -f`한다. |
| `node_modules/`, `backend/.venv/`, `dist/` | 재생성 가능하지만 서버·도구가 사용할 수 있다. 실행 중인 프로세스를 확인하고, 필요할 때만 삭제한다. 평상시에는 설치된 의존성을 유지한다. |
| `.codegraph/`, Python 캐시, 브라우저 임시 로그 | 사용 중이지 않을 때 정리할 수 있다. `.codegraph` 재생성은 프로젝트 래퍼와 [도구 안내](RESTART_WITH_OMO_AND_CODEGRAPH.md)를 따른다. |
| DB·백업·읽기 전용 검증 원본 | 자동 삭제하지 않는다. 실제 실행 DB와 역사적 마이그레이션 fixture를 구분한다. |
| `.git/` | 직접 일괄 삭제하지 않는다. 열려 있거나 생성 중인 pack/index/lock은 보존한다. 최근 미참조 객체는 복구 여지를 위해 즉시 prune하지 않는다. |

## 작업마다 지킬 절차

1. 시작 전 `du -hd 1 .`과 `df -h .`로 폴더 사용량과 실제 여유 공간을 기록한다. 서버 PID·작업 디렉터리·DB·출력 경로를 확인한다.
2. 새 단위 검증은 관리 도구의 고유 실행 폴더에 `runtime/`과 `evidence/`를 나누어 쓴다. 로더·자산 파이프라인 출력 경로는 wrapper가 지정한다. 브라우저 QA는 먼저 과거 증거 한도를 검사하고 기존 소유권 계약을 따른다.
3. QA용 작업 사본에는 필요한 소스와 fixture만 복사한다. `.omo`, `.git`, 의존성, 과거 영상·trace를 통째로 재귀 복사하지 않는다. 테스트가 요구하는 역사적 입력은 위 목록으로 명시한다.
4. 실행 종료 후 자신의 runtime·임시 빌드를 정리한다. 로그, 실패 증거, 수락된 최종 증거와 재현 입력은 보존한다. 오래됐다는 이유만으로 실패 이력을 삭제하지 않는다.
5. 중복 보고서는 보존 사본의 SHA-256과 크기를 확인한 뒤 중복본만 삭제하고, 삭제 경로·보존 경로·해시를 기록한다. 유일본 또는 참조 관계가 불명확한 파일은 남긴다.
6. macOS APFS에서는 사용하지 않는 동일 파일의 사본을 copy-on-write clone으로 교체해 경로·내용을 유지할 수 있다. 교체 전후 해시와 파일 변경 여부를 검사하고 원래 권한·수정 시각을 보존한다. 쓰기가 공유되는 하드링크는 사용하지 않는다. 읽기 전용 디렉터리는 건너뛴다. `du`는 공유 블록을 중복 계산할 수 있으므로 확보 공간은 `df` 차이로 확인한다.
7. 커밋 전 `git diff --cached --check`, 포함 파일·크기·비밀정보 패턴·LFS 포인터를 확인한다. 필수 입력이 Git에서 빠지지 않았는지도 검증한다. 검증 실패는 숨기지 않고 범위와 함께 기록한다.

## 정리 주기와 용량 예산

- 각 QA 작업 종료 시 자신이 만든 runtime과 임시 빌드를 정리한다.
- 주 1회 또는 여유 공간이 30GiB 미만일 때 로컬 증거 용량과 중복을 점검한다. 자동 삭제 예약은 만들지 않는다.
- 새 관리 실행은 1GiB에서 중단한다. 브라우저 산출물도 1GiB를 기준으로 복사 범위·영상 길이·프레임 JSON 저장량을 점검한 뒤 다음 실행을 결정한다. 증명에 필요한 프레임이나 실패 기록을 임의로 줄이지 않는다.
- 과거 증거를 외부 보관으로 옮길 때는 먼저 경로·크기·SHA-256 목록과 복원 절차를 만들고, 백업에서 실제 복원·해시 검증 후 로컬 원본을 정리한다. Git push만으로 제외된 증거가 백업됐다고 간주하지 않는다.

## 2026-11-06 정리 범위

원본 자산·DB·실행 중인 데모·도메인 코드는 유지했다. 루트의 잘못 배치된 검증 파일은 `.omo/evidence/recovered-root-20261106/`로 옮겼다. 중복 보고서는 해시로 대조했고, 오래된 증거의 중복 사본은 APFS clone으로 교체했다. 상세 로컬 작업 영수증은 Git 제외 경로 `.cleanup/`에 있다. 공유 가능한 결과와 기존 테스트 실패는 [정리 검증 기록](maintenance/cleanup-2026-11-06.md)에 남긴다.
