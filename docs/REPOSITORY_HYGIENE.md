# 저장소와 디스크 정리 원칙

소스의 재현성과 검증 원본을 보존하면서, 임시 산출물이 Git과 디스크에 반복 축적되지 않게 관리한다. Git 제외는 파일 삭제나 백업을 뜻하지 않는다.

## 보관 기준

| 구분 | 보관·정리 원칙 |
| --- | --- |
| `src/`, `backend/`, `tools/`, `scripts/`, 설정·잠금 파일 | Git에 보관한다. 실행 DB·캐시·가상환경은 제외한다. |
| `assets/source/`, `public/assets/`, `shared/`, `tests/fixtures/` | 원본 제작 자료와 실제 실행·테스트 입력이므로 보존한다. 크기만으로 삭제하지 않는다. |
| 대형 필수 파일 | `shared/fixtures/finishing-continuity-cases.json`은 정확한 바이트를 유지하는 Git LFS 파일이다. 복제 후 Git LFS를 설치하고 `git lfs pull`을 실행한다. |
| `docs/evidence/` | 문서·JSON·참고 이미지는 Git에 보관한다. 대용량 ZIP·영상은 로컬 원본으로 남기고 Git에서 제외한다. 새 clone에는 제외한 영상·trace가 없으며, 원본이 필요하면 별도 백업에서 가져온다. |
| `.omo/` | 실행 이력·실험·검증 작업 사본은 기본적으로 로컬에 보존한다. 현재 테스트/출처 검증이 직접 읽는 예외 파일만 Git에 포함한다. 정확한 목록과 SHA-256은 [필수 과거 입력 목록](maintenance/retained-test-inputs.json)에 있다. 이미 추적한 예외 파일은 일반 `git add`로 갱신할 수 있다. 새 예외는 의존성을 확인하고 목록을 갱신한 뒤 그 경로만 `git add -f`한다. |
| `node_modules/`, `backend/.venv/`, `dist/` | 재생성 가능하지만 서버·도구가 사용할 수 있다. 실행 중인 프로세스를 확인하고, 필요할 때만 삭제한다. 평상시에는 설치된 의존성을 유지한다. |
| `.codegraph/`, Python 캐시, 브라우저 임시 로그 | 사용 중이지 않을 때 정리할 수 있다. `.codegraph` 재생성은 프로젝트 래퍼와 [도구 안내](RESTART_WITH_OMO_AND_CODEGRAPH.md)를 따른다. |
| DB·백업·읽기 전용 검증 원본 | 자동 삭제하지 않는다. 실제 실행 DB와 역사적 마이그레이션 fixture를 구분한다. |
| `.git/` | 직접 일괄 삭제하지 않는다. 열려 있거나 생성 중인 pack/index/lock은 보존한다. 최근 미참조 객체는 복구 여지를 위해 즉시 prune하지 않는다. |

## 작업마다 지킬 절차

1. 시작 전 `du -hd 1 .`과 `df -h .`로 폴더 사용량과 실제 여유 공간을 기록한다. 서버 PID·작업 디렉터리·DB·출력 경로를 확인한다.
2. 새 검증은 고유 실행 폴더 하나에 `runtime/`과 `evidence/`를 나누어 쓴다. 로더 테스트는 `ASSET_LOADER_EVIDENCE_ROOT`, 자산 빌드 테스트는 `ASSET_PIPELINE_EVIDENCE_ROOT`를 명시해 루트에 산출물이 생기지 않게 한다.
3. QA용 작업 사본에는 필요한 소스와 fixture만 복사한다. `.omo`, `.git`, 의존성, 과거 영상·trace를 통째로 재귀 복사하지 않는다. 테스트가 요구하는 역사적 입력은 위 목록으로 명시한다.
4. 실행 종료 후 자신의 runtime·임시 빌드를 정리한다. 로그, 실패 증거, 수락된 최종 증거와 재현 입력은 보존한다. 오래됐다는 이유만으로 실패 이력을 삭제하지 않는다.
5. 중복 보고서는 보존 사본의 SHA-256과 크기를 확인한 뒤 중복본만 삭제하고, 삭제 경로·보존 경로·해시를 기록한다. 유일본 또는 참조 관계가 불명확한 파일은 남긴다.
6. macOS APFS에서는 사용하지 않는 동일 파일의 사본을 copy-on-write clone으로 교체해 경로·내용을 유지할 수 있다. 교체 전후 해시와 파일 변경 여부를 검사하고 원래 권한·수정 시각을 보존한다. 쓰기가 공유되는 하드링크는 사용하지 않는다. 읽기 전용 디렉터리는 건너뛴다. `du`는 공유 블록을 중복 계산할 수 있으므로 확보 공간은 `df` 차이로 확인한다.
7. 커밋 전 `git diff --cached --check`, 포함 파일·크기·비밀정보 패턴·LFS 포인터를 확인한다. 필수 입력이 Git에서 빠지지 않았는지도 검증한다. 검증 실패는 숨기지 않고 범위와 함께 기록한다.

## 정리 주기와 용량 예산

- 각 QA 작업 종료 시 자신이 만든 runtime과 임시 빌드를 정리한다.
- 주 1회 또는 여유 공간이 30GiB 미만일 때 로컬 증거 용량과 중복을 점검한다. 자동 삭제 예약은 만들지 않는다.
- 한 번의 검증 산출물이 2GiB를 넘으면 반복 실행 전에 복사 범위·영상 길이·프레임 JSON 저장량을 점검한다. 증명에 필요한 프레임이나 실패 기록을 임의로 줄이지 않는다.
- 과거 증거를 외부 보관으로 옮길 때는 먼저 경로·크기·SHA-256 목록과 복원 절차를 만들고, 백업에서 실제 복원·해시 검증 후 로컬 원본을 정리한다. Git push만으로 제외된 증거가 백업됐다고 간주하지 않는다.
